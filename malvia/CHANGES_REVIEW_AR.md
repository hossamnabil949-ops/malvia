# تغييرات جولة المراجعة (المراحل 2 و3 و4)

## المنطق (src/utils/saleLogic.ts + App.tsx + QuickPosView.tsx)
- التحقق من الرصيد قبل البيع (الكارت + الدفع + إعادة تحقق في handleCreateInvoice). لا إخفاء للفرق بـ Math.max.
- مطابقة الصنف بـ partId (كان بالاسم أو الرقم). الفاتورة تحمل partId/customerId/cashierId.
- دفع مقسّم (كاش + فيزا ...) وكل طريقة تدخل حسابها بالخزنة؛ الآجل على حساب العميل.
- نسبة الضريبة من الإعدادات، منع البيع بأقل من التكلفة لغير المدير، حساب الإجماليات بالقروش.
- سجل التدقيق (auditLog) ودفتر حركات المخزون (stockMovements): موارد جديدة متزامنة، تُعرض في المالية > «سجل التدقيق وحركات المخزون».

## الـ API (api/_security.ts وغيره)
- /api/sync: تحقق من الجسم (المورد/النوع/التكرار/الحجم 3MB)، حد معدل، مقارنة أسرار بزمن ثابت.
- /api/ai/command: يتطلب مفتاح ترخيص صالحاً + حد معدل، ولا يُرسل سعر التكلفة ولا هواتف/أرصدة العملاء لجوجل.
- registry / backup / cron: مقارنة آمنة للتوكن، وأخطاء بكود (حقل code) بدون تسريب رسائل داخلية.
- الواجهة: خطأ امتلاء localStorage يظهر بدل ما يُبتلع.

## لم يُنفَّذ بعد
- تجزئة كلمات المرور وتسجيل دخول على السيرفر (يحتاج endpoint وجلسات).
- فصل App.tsx إلى خدمات/Hooks، وترحيل التخزين لجداول (انظر malvia_schema_proposed.sql).
- ربط سطر المرتجع بمعرّف سطر الفاتورة (لا يزال بالاسم+الرقم)، وإلغاء الفاتورة (Void)، والورديات.
